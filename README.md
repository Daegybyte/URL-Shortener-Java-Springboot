
# URL Shortener Java Springboot

A URL shortener backend built with Java and Spring Boot. The goal is to go beyond a basic CRUD tutorial and build the parts that usually only get discussed on a whiteboard: random code generation, caching, rate limiting, async analytics, and observability, with measured results.

## Cheatsheet: get running again

Open a terminal in the `shortener` folder (the one with `pom.xml`).

### Start of day

1. Open Docker Desktop and wait until the engine shows as running.
2. Confirm Docker is up:
   ```bash
   docker info
   ```
   It should print a Server section, not an error.
3. Start Postgres and Redis:
   ```bash
   docker compose up -d
   docker compose ps
   ```
   Both `postgres` and `redis` should say Up. Give Postgres 5 to 10 seconds on a cold start.
4. Run the app (leave this tab open):
   ```bash
   ./mvnw spring-boot:run
   ```
   Look for `Started ShortenerApplication` near the end of the log.
5. In a second tab, check health:
   ```bash
   curl localhost:8080/actuator/health
   ```
   You want `{"status":"UP"}`.

./mvnw test -Dtest=ShortCodeGeneratorTest
```

### If something breaks

| Symptom | Likely cause and fix |
| --- | --- |
| `cannot connect to the Docker daemon` or `docker.sock: no such file` | Docker Desktop is not running. Run `open -a Docker`, wait, then retry. |
| `Connection to localhost:5432 refused` when starting the app | Postgres is not up. Run `docker compose up -d` and wait a few seconds. |
| `zsh: no such file or directory: ./mvnw` | Wrong folder. Run `pwd` and `ls`, then `cd` into the folder that contains `mvnw` and `pom.xml`. |
| Flyway checksum mismatch | An already-applied migration was edited. In dev with no real data, reset with `docker compose down -v` then `docker compose up -d`. Otherwise add a new `V2__...sql` file. |
| `relation "..." does not exist` or Hibernate schema validation error | Entity and table do not match, or the migration has not run. Compare the entity fields with `\d links`. |
| `cannot find symbol` at compile time | Usually a missing import. Imports only apply to the file they are written in. |
| Port 8080 already in use | An old run is still going. Stop it with `Ctrl+C`, or find it with `lsof -i :8080`. |
| No autocomplete or formatting in VS Code | Java language server problem. Open the `shortener` folder itself, run `Java: Clean Java Language Server Workspace`, and check `Java: Configure Java Runtime` lists JDK 25. |
| `Bad CPU type in executable` in the Java extension log | An Intel-only JDK is installed on Apple Silicon. Remove it from `/Library/Java/JavaVirtualMachines/`. |

  endpoints:

The credentials above are local development defaults from `docker-compose.yml` and must not be reused anywhere real.

## Database

Flyway owns the schema. Hibernate is set to `ddl-auto: validate`, so it only checks that entities match the tables and never changes them. Migrations live in `src/main/resources/db/migration/`.

Rule: never edit a migration that has already been applied to a database with data in it. Add a new versioned file instead. Flyway checks checksums and will refuse to start if an applied migration changes.

### `links` table

```sql
CREATE TABLE links (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    original_url TEXT NOT NULL,
    short_code   VARCHAR(16) NOT NULL,
    expires_at   TIMESTAMPTZ,
    is_active    BOOLEAN NOT NULL DEFAULT TRUE,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uq_links_short_code UNIQUE (short_code),
    CONSTRAINT chk_links_short_code_len CHECK (char_length(short_code) BETWEEN 1 AND 16)
);
```

The unique constraint on `short_code` also creates the index that redirect lookups need.

## Design decisions

**Random short codes, not sequential IDs.** Encoding an incrementing number makes codes guessable and lets anyone enumerate every link. Instead, the primary key is a UUID and the short code is generated separately as random characters, so codes reveal nothing about creation order or volume.

**Code generation.** `ShortCodeGenerator` picks each character independently from a 62-character alphabet (`0-9`, `A-Z`, `a-z`) using `SecureRandom`. Each character is uniformly distributed and the length is always exactly what was requested. At the default length of 7 there are roughly 3.5 trillion possible codes.

**Collisions.** Two links could, rarely, get the same code. The unique constraint on `short_code` is the source of truth. The service will catch the violation and retry with a new code, with a cap on retries.

**Invalid lengths fall back to a default.** `randomCode` with a length below 1 quietly uses the default length of 7 instead of throwing. This is a deliberate choice for this utility. Validation of user input belongs at the API boundary, where bad requests should get a clear 400 response.

**Utility class.** `ShortCodeGenerator` is `final` with a private constructor, since it contains only static methods and holds no per-object state. A single shared `SecureRandom` instance is reused because it is expensive to create and thread-safe.

**Two flags for disabling links.** `expires_at` handles automatic expiry and `is_active` handles manual deactivation. The redirect logic will treat a missing, inactive, or expired link as not found.

## Tests so far

`ShortCodeGeneratorTest` covers:

- the returned code has the requested length
- every character is in the alphabet
- 10,000 generated codes are all distinct
- lengths of zero and below fall back to the default length

## Notes on the environment

- Developed on macOS (Apple Silicon) in VS Code.
- Spring Boot 4 renamed some starters (for example `spring-boot-starter-webmvc` and `spring-boot-starter-flyway`). Many online examples still target Spring Boot 3, so an API may have moved if a snippet does not compile.
- The Flyway PostgreSQL module (`flyway-database-postgresql`) is a separate dependency and is required for Postgres.
